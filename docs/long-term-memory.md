# Markdown 关联记忆

长期记忆由主 Agent 按需读取和维护。Markdown 文件是唯一内容来源，没有知识数据库、固定分类、自动提取／整合、后台自动学习或模型召回筛选。另提供手动 Dream，围绕用户指定的主题搜索历史片段，维护同一套 Markdown 记忆。OM 的 observations/reflections 继续只负责当前会话压缩，不参与这条链路。

## 存储与范围

```text
$PIG_DIR/memory/
├── global/
│   ├── MEMORY.md
│   └── <主题>.md
└── projects/<项目身份 SHA-256>/
    ├── MEMORY.md
    └── <主题>.md
```

各 scope 内可以按需创建主题文件夹和嵌套子目录；`MEMORY.md` 固定在 scope 根目录，通过标准 Markdown 相对链接关联笔记。

开发默认 `cwd/.pig`，安装版默认 `~/.pig`；`PIG_DIR` 优先。项目身份沿用可靠 Git common dir，否则使用真实 cwd，因此同仓库 worktree 共用目录。Chat scratch 不继承外层开发仓库，只提供 global。Agent 不能传任意项目身份或本机绝对路径；UI 可检查全部项目文件。

global 是跨项目共用内容，不是绕过项目范围的副本库。项目实现细节应写在 project；记忆不构成上传、联网、命令执行等权限授权。

配置为 OM namespace 内独立的 `fileMemory: { enabled: boolean }`，缺省时默认开启，用户明确保存的 false 保持关闭。旧 `longTerm` 配置、独立模型配置和 SQLite 文件完全不读取、不迁移，也不自动删除。四个 memory_* 工具始终注册为 deferred，pig_servers 始终保留 memory 入口；关闭时仍有英文 memory 章节，说明当前不可用、引导用户在「人格与记忆 → 文件记忆」开启，并禁止用普通文件或命令工具绕过，也不能声称已持久保存。工具执行时读取当前开关，关闭返回 MEMORY_DISABLED 和相同英文引导，不读取或修改笔记；排队的修改在提交前重新检查。切换沿用空闲资源重载，当前有效说明通过 SDK 章节补丁替换，不擦除旧历史。原始聊天、OM 与人格数据不改动。

## 入口与按需阅读

`MEMORY.md` 只是很小的回忆起点，放有区分度的线索、简短说明和主题链接，不是知识正文。Agent 可以自由组织主题文件和 Markdown 相对链接，没有强制类型或 frontmatter。

系统提示词的 `memory` 章节仅包含简短英文使用说明：需要记忆时通过 tool_search 加载 memory_ 工具，先读取对应 scope 的 MEMORY.md，再沿链接阅读；索引缺失或为空时可列出文件，其他记忆仍可能存在。global 和 project 的索引及主题正文都不自动注入。每份索引仍限制为 4 KiB／60 行，末尾换行不额外算一行、真实空白行仍计数；这些限制仅用于文件保存，不再用于系统提示词预览。

在 SDK `before_agent_start` 中按启用状态选择正常／关闭引导并设置 `systemPromptOptions.sections.memory`，不读取记忆文件，不返回强制 systemPrompt，也不通过 `context` 追加临时消息。索引创建、修改、删除或项目切换均不改变这段使用说明；当前文件内容通过 memory_read 按需读取。Pi 仅在使用说明或启用状态变化时按章节差量机制更新，旧的带索引正文的章节会被完整替换为使用说明。
四个工具通过 `deferred` 和 `memory` namespace 由 `tool_search` 渐进加载，工具目录沿用 `pig_servers`。没有每轮辅助模型请求或强制读取目录的动作。

## 四个工具

- `memory_read(scope, path?, from?, query?, offset?, limit?)`：不传 path/query 时列目录；query 为字面文本搜索；path 读取一份笔记或原样接收 Markdown 相对链接。from 为来源笔记的规范路径（复制上次返回的 file.path），工具以其所在目录解析 `./`／`../`；省略 from 时以 scope 根目录解析。from 必须与 path 一起使用，path/query 互斥。返回 file.path 是 scope 根下的规范路径，可直接用于编辑／删除，或作为下一次读取的 from。文件 offset 是零起始行偏移，目录／搜索 offset 是条目偏移，跟随 nextOffset。每页最多 200 行／条，输出按字节进一步限幅。revision 总是完整文件的 SHA-256，即使只读了一页。
- `memory_add(scope, path, content)`：只创建，不覆盖已有文件；重复添加报 `MEMORY_ALREADY_EXISTS`，与 edit/delete 的 `MEMORY_REVISION_CONFLICT` 区分。一般先查相关笔记再决定是否需要新建；添加后检查对应 scope 的 MEMORY.md，不存在则通过记忆工具创建，并维护有价值的入口链接。
- `memory_edit(scope, path, revision, oldText, newText)`：唯一精确文本替换；只有现有文件为零字节时，允许 oldText 为空、用 newText 初始化，无需删除重建。仅含空白的文件不是零字节，不能使用这一特例；revision 必须来自读取，空文件初始化也严格检查版本。冲突先重读再判断，不盲重试，不支持整目录重写。
- `memory_delete(scope, path, revision)`：删除单个 Markdown 文件，不递归删目录。永久删除，不影响原始会话；没有旧方案的来源封禁、替代链或遗忘级联。相关链接由 Agent 局部维护，不静默改写其他文件。删除后在 catalog writer lease 内用非递归 rmdir 向上回收空父目录，保留 scope 根及其外层目录；遇到非空目录（含隐藏文件／链接）停止，不删除其内容。其他清理失败明确报告文件已删除但目录回收失败，不宣称回滚；不额外扫描清理历史遗留空目录。

scope 只能是 global 或当前 project。read 工具说明明确索引名为 `MEMORY.md`，对应各自 scope 根；需要完整索引或 revision 时可直接传 `scope` 和 `path: MEMORY.md`。Markdown 链接按标准相对所在笔记的目录，不引入虚拟路径或强制平铺。Agent 无需换算：例如从 `guides/start.md` 跟随 `../testing.md` 时，传 `from: guides/start.md, path: ../testing.md`，返回 `file.path: testing.md`。底层拒绝越出 scope 的回退（固定 code `MEMORY_LINK_OUTSIDE_SCOPE`）、绝对路径、URL、编码路径、隐藏路径；解析后的读取仍执行既有符号链接／硬链接检查。编辑／删除继续使用返回的规范路径，不接收 from 或 `../`。主题文件最多 64 KiB，单行最多 15 KB，确保工具能分页读取。索引限额在提交前校验，超限不会保存。所有记忆读取均经工具返回，结果用自适应 JSON fence 标为不可信历史数据，不作为指令或授权。

## 记忆维护

工具说明采用英文，以查看／添加／修改／删除记忆的方式描述，不把 Markdown 格式当成主要概念。read 明确说明列目录、搜索、读文件的参数选择，以及链接解析、分页和版本的用法。add 要求先查相关记忆、优先补充已有内容；edit 要求先读、唯一精确替换（零字节文件允许空 oldText 初始化），冲突后重读；delete 明确单文件永久删除。维护受影响的链接和索引，不保存密码、密钥等敏感信息。主题笔记 add／edit 成功返回 path、revision 和 reminder，提醒检查同 scope 的 MEMORY.md、缺失时创建并维护入口；直接写根 MEMORY.md 不返回这一提醒，避免反复维护索引的循环。底层不代写摘要，不自动把所有主题放入索引。

Agent 按需维护记忆，没有强制补记忆轮次或后台定时器。

## 安全与并发

文件工具只开放记忆根内的路径，拒绝绝对路径、遍历、隐藏路径、符号链接、硬链接及非普通文件。目录 0700、文件 0600。UTF-8 严格解码，损坏和 IO 错误明确报错。读取失败保留 ENOENT 等错误码，只展示 scope 内相对路径，不返回底层错误的真实磁盘路径或原始 cause。常见凭据模式拒写，但不宣称这是对任意敏感内容的完整识别。

默认／完全访问模式允许专用工具在受限目录内维护记忆，无逐条人工准入；只读模式拒绝全部修改，读取仍可用。取消及实际提交前重新检查权限。普通 bash／文件工具继续受已有沙箱保护，不能用它们绕开记忆接口。

全体 global／project 笔记共用 `memory/` 的遍历预算与 writer lease：最多 1000 个 Markdown 文件、2000 个非隐藏条目，目录深度从 `memory/` 起最多 8 层（包含 scope 目录）。写入在锁内检查新增文件和目录的预算，超限时不创建目标目录、不落盘；达到容量上限仍可编辑已有文件。深度／文件数／条目数超限分别使用固定 code `MEMORY_DEPTH_LIMIT`／`MEMORY_FILE_LIMIT`／`MEMORY_SCAN_LIMIT`。搜索只保留当前分页，找到下一条匹配即可返回，不累计全库匹配行。

写入采用目录 writer lease、revision 比较和临时文件 rename；并发写者返回 busy，过期版本返回 conflict，不自动覆盖。崩溃遗留 lease 仅在其 PID 已不存在时回收；无法确认的 lease 报错，不抢锁。提交临界区无异步等待。该机制防协作实例的丢更新，不宣称隔离拥有同一本机账号权限的恶意进程。

## 设置页

人格与记忆 → 长期记忆提供文件记忆开关和 Markdown 文件浏览器。开关保存失败后重新读取持久化配置；若重读也失败，明确显示两次错误并将配置标为未知、禁用开关，提供重新读取按钮，仅在成功读到配置后恢复操作。没有五分类列表、模型选择、后台队列、学习用量或自动召回诊断。文件可查看、编辑、保存、删除；保存／删除使用相同 revision 校验，失败保留草稿，未保存关闭或切换文件需确认；切换笔记会取消上一份笔记的删除确认。UI IPC 仅所属主 frame 可调用。滚动保留但隐藏滚动条。

### 外部修改与手动修复

文件浏览使用独立的有界容错扫描，不放宽普通记忆工具的存储校验。正常文件继续展示；错放在 `global/`、`projects/<合法项目 ID>/` 范围之外的 Markdown、超大／不可读文件和符号链接分别列出相对路径及原因。符号链接不跟随。单项异常不拖垮整个页面；根目录无法访问则明确报错，数量／深度／条目超限明确标记列表不完整，不伪装成完整结果。项目名称解析失败只回退到 ID，不猜身份。

有可读取的错放文件时展示「修复记忆」。只有点击才启动专用 Agent；文件记忆关闭时也可以修复，不修改开关。共用 Dream 的单飞状态、关闭弹窗后台执行、停止、预算、私有 JSONL、暂存、before 备份、冲突检查和发布机制；通过同一 UI-only start/status/stop IPC，修复请求为 `{repair:true}`。修复不发现或搜索历史会话，使用独立英文提示词，模型只能看到四个 scoped 记忆工具及 `repair_read/repair_delete`，后两者只操作宿主提供的错放文件白名单。`repair_read` 不传 path 时分页列出来源；传 path 时按 UTF-8 字节分页，每页正文最多 16,000 字节，不截断多字节字符，长行也可完整读取。续页直接沿用 nextOffset，各页 revision 均为完整原文件的版本；删除仍校验完整 revision。普通 memory_read 仍按行分页。

修复可以创建主题笔记、补充已有文件、丢弃重复或无价值内容，并维护 scope 根的 MEMORY.md 和相关链接（有需要时创建索引）；确认内容保存后删除错放原文件。不顺便重整正常文件。项目 ID 只来自宿主列出的已有 scope 或可可靠解析的已注册项目，归属不明保留并报告。超大、无权限、符号链接等只提示手动处理，扫描不完整时不启动修复。暂存只复制可安全读取的文件，未复制的异常项保留原样且不得被覆盖；发布仍计算它们占用的目录／文件额度，并拒绝源文件发生并发变化。修改提交失败使用同一备份恢复，不宣称跨文件崩溃原子性。

## 手动 Dream

入口在「人格与记忆 → 长期记忆 → 做梦」。用户必须指定一个主题或几个相关问题，只有手动触发。从设置打开时先显示做梦记录，合并做梦与修复回执，以 Badge 区分类型，可只读查看日期、状态、报告、统计与修改清单；右上角新增按钮进入主题输入。文件记忆关闭时仍可查看旧记录，但不能新增做梦。打开页面只读取运行状态和已保存的 result.json，不枚举或扫描原始会话历史；开始后由 Agent 围绕主题搜索线索、读取命中片段，必要时扩大上下文。没有时间范围、整份会话模式、全量已处理队列或“必须读完”的要求。

### 提示词与工具

提示词在 `src/main/features/memory/dream/prompt.ts`，采用用户确认的英文稿：不是总结会话或尽量多写；只维护相关记忆，允许不修改；有关键疑点才检查工具记录；未查看、省略或未确认的信息不得声称已核实。先读取相关 scope 的 MEMORY.md；缺失或为空时列目录、查相关笔记，不假定目录为空。没有记忆时从历史搜索开始，有价值内容才创建主题笔记及入口，不建空索引。

- `dream_history_search(query, projectId?, sessionId?, cursor?)`：必填字面查询，搜索用户输入与最终回复，每页最多 20 个命中；返回片段、项目归属、原 cwd、会话／轮次 ID、时间、可靠的 projectId（可确认时）以及分页游标。
- `dream_history_read(sessionId, turnId, before?, after?, cursor?)`：读取已定位轮次，默认前后各一轮，单次扩展各最多十轮；长片段分页，每页约 14K 字符，标识不完整内容。可逐步扩大范围，不默认读取整份会话。
- `dream_turn_tools(sessionId, turnId, cursor?)`：按需读取已定位轮次的调用及结果，JSON 文本分片每页 12K 字符；思考不返回，附件／省略内容明确标记。
- 四个 `memory_*` 工具继续复用普通会话的实现及说明，仅 Dream schema 增加可选 projectId。global 禁止携带 projectId；project 必须使用历史工具提供的可靠 ID，宿主校验映射，不能猜目录、hash 或借此拓宽普通会话能力。

原目录删除的项目仍保留原名称与路径，身份未确认时不创建项目记忆、不归为 Chat；真正跨项目内容才能写 global，项目细节不能因此变成全局规则。已知 Chat 目录删除后仍为 Chat。目录缺失之外的权限和 IO 错误照常报告。

### 有界读取与执行

历史来自 SDK 共用 sessions 目录，发现阶段复用文件枚举，只读每份文件最多 1 MiB 的会话头，不调用 SDK 的全正文 listAll，也不为生成标题读取消息；显示项目目录名与会话短 ID，按文件修改时间排序。目录元数据与内容分开加载，读取／解析失败直接报告，不静默遗漏。首次搜索到某文件才按 64 KiB 字节流建立当前分支索引，每行只保留首尾各 8 KiB 探针，记录正文的字节偏移；不把整份 JSONL 或巨型工具行解码为字符串。只缓存最近八份索引，被淘汰后重建仍固定到该文件首次读取的大小与分支。

普通搜索／阅读只解析需要的用户与最终回复记录，工具正文只有专用工具请求时才读取。单条原始记录超过 8 MiB 时明确标记省略，搜索报告省略数量，不把省略视为已完整查证；正文输出继续分页。无法解释的布局或损坏来源明确失败，不自动迁移、修改或重建历史文件。

独立 SDK runtime 只暴露三个历史工具与四个记忆工具，无人格、OM、Skills、MCP、Codemode、普通文件、命令或浏览器工具，也不能递归创建 Agent。使用共享默认模型／思考强度，不另存模型偏好。首次请求通过 SDK 同步 beforeStart 门控再次校验取消与权限，异步输入／鉴权期间已取消的运行不得在预检结束后发出模型请求；运行中的请求仍由 abort 中止。预算为 2000 万累计 tokens（新输入、缓存读取、缓存写入与输出之和）或 SDK 估算 $20，不限制总运行时间、模型轮次或请求次数。达到任一预算的 80% 时，向同一运行只投递一次收尾指令：停止扩大搜索，核查已有发现、修复受影响索引链接并报告未解决问题；预留预算用于完成验证及发布，收尾期间不再被工具活动覆盖为搜索／维护状态。累计用量在请求结束后更新，单次请求可越过硬上限；达到硬上限仍中止且不发布未完成暂存，不承诺分轮保留成果。用量分别展示新输入、缓存读取、缓存写入、输出及总量；SDK 费用缺失或为零时显示未知，已有正值仍计入费用上限。估算不等于供应商账单。预算中止单列为 limited，并保存及显示 tokens／费用原因、实际用量与上限，不再只给通用 DREAM_BUDGET。

### 暂存、提交与状态

所有记忆修改进入单次运行的暂存区。模型结束后核对实际引用记录的摘要与会话身份，在 catalog writer lease 内复查记忆 revision、授权项目范围、文件限制及受影响链接，再发布并保留 before 备份和 changes 清单。发布前按真实目录（含既有空目录）校验文件数、深度和条目额度，计入新增父目录并扣除本批删除的文件，不仅检查暂存区。链接只验证修改的笔记和指向本批删除目标的引用，无关旧笔记的无效链接不阻塞发布。普通同步 IO 失败尝试恢复，并回收本批创建的空目录，不宣称跨文件崩溃原子性；发布后清理或回执失败需按错误码、清单和备份检查部分结果。

数据为 `$PIG_DIR/dream/<run id>/{session.jsonl,result.json,before/,changes.json}`，0600／0700；暂存目录结束时清理。回执含主题、结果报告、用量、修改清单及固定错误码，没有知识 DB 或已处理历史检查点；旧 checkpoints.json 不读取、不迁移、不自动删除。同一主题可以再次回顾。独立 SDK SessionManager 将完整会话持续追加到本次目录的 session.jsonl（含提示词、消息、工具调用／结果及压缩记录），在首次消息前以 0600 创建；失败、停止后也保留。它不在普通 Pi sessions 目录，不进入会话列表或后续 Dream 的历史来源，不能跨重启续跑；原始会话内容可能敏感，仅靠私有目录及文件权限保护。

界面区分记录列表、只读详情、主题输入与实时运行状态，报告复用 MarkdownText，文件行突出 scope 内路径、完整路径放 tooltip，用量在右上角统计弹层展示；只有正文滚动且隐藏滚动条。修复详情不显示底部按钮，只通过右上角关闭图标关闭，运行中的停止按钮移到标题栏；历史详情也不提供修改或重新运行按钮。运行时明确提示可以关闭弹窗后台执行。侧栏底部 glass/solid 左侧的月亮按钮展示同一份状态，运行外环转动、失败红点，点击返回详情而不创建任务；任务结束后查看详情再关闭即隐藏该次图标，后续轮询不会使它重新出现，运行中关闭则保留。Sidebar 与全局 DialogHost 共用引用计数轮询和请求 revision，旧轮询不能覆盖 start／stop 回复。界面显示准备目录／搜索／阅读／维护／提交、当前线索、用量、报告、修改文件及固定错误码，不显示会话完成比例。只有所属 UI 主 frame 的 `memory:dream:start/status/stop` IPC 可控制，`memory:dream:list/read` 只读回执。列表每页最多 30 条，单份 result.json 最多 2 MiB；早期回执缺少缓存分项和费用可信度时只读兼容，保留原始数据、将相关统计显示为未知，不把旧输入当成新输入，不迁移回执；已存在但类型错误的字段仍报错。校验运行 ID、内容与文件类型，拒绝符号链接、硬链接和越界路径，不读取或暴露 JSONL；错误不泄漏原始 JSON 或绝对存储路径。关闭普通对话框不停止任务；所属窗口重载／退出、关闭文件记忆或默认权限变化会取消本次运行，切回权限不能复活。未提交修改取消后丢弃。应用退出经轻量 lifecycle hook 停止，未使用时不初始化 Dream 模型运行时。

## 参考与边界

- [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)：小入口、按需展开、关联表示，以及写记忆的注意力成本。
- [Dreaming with a dynamic workflow](https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow)：逐会话查证，随后整理关联与索引；Pig 不照搬多 Agent 编排。
- [Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)：宿主执行受限文件操作、精确替换和路径边界。
- [Claude Code auto memory](https://code.claude.com/docs/en/memory)：MEMORY.md 索引常驻、主题文件按需读取。

四个工具拆分与 deferred 是 Pig 的接口选择，不是官方比较实验得出的最优结论。没有向量检索、普通会话的跨项目任意读取、常驻自动链接修复或删除后禁止未来重新学习的机制。Dream 的跨会话回查是本次手动运行的独立授权，不向普通会话开放。
