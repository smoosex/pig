# 跨会话学习与长期记忆

## 目标与链路

理解用户做过的项目与开发／协作偏好，并从真实开发中积累可复用的经验教训。不是保存更多会话流水账。

```text
原始会话 JSONL
├─ OM observation / reflection → 当前会话压缩与续作
└─ 增量原始消息证据窗口 → 无工具任务学习
                         ↓
                   任务经历 + 临时知识提议
                         ↓
              相关既有知识 → 无工具知识整合
                         ↓
       用户偏好 / 项目档案 / 项目知识 / 经验教训
                         ↓
       分类全文检索 + 明确偏好候选 + 增量价值筛选
```

长期学习不再经过 reflection，不受 Reflector 的生成阈值限制；OM 整理失败不会阻止独立学习，学习失败不阻止 OM 或主任务。

## 首次接入与清空

数据库在 `longTermMemoryPath()`：安装版为 `$PIG_DIR/memory/long-term.sqlite`（通常 `~/.pig/memory/long-term.sqlite`），开发默认 `cwd/.pig/memory/long-term.sqlite`。`PIG_DIR` 优先级最高。

只维护当前结构，不设置数据库版本号，不迁移旧 reflection 候选库。检测到旧 `memory_candidates` 表会明确报错，绝不静默覆盖或清空。

开启自动学习后，每个会话首次接入会建立持久化基线：当时当前分支的历史 entry 直接标记已处理，不送模型；只学习之后的新消息。基线在等待设置之前捕获，快速发送的首条新消息不能被误算为旧历史。切换到旧 sibling 分支时，早于会话接入时间的原始消息也不参与新学习。这保证清空派生库后重新打开旧聊天，不会自动把旧内容补学回来。正常重载复用已有基线和检查点。

关闭所有使用同一数据目录的 Pig 实例后，可删除主库及可能的 sidecar 文件：

```bash
rm -f "$HOME/.pig/memory/long-term.sqlite"{,-wal,-shm,-journal}
```

该命令用于默认安装目录；自定义 `PIG_DIR`／开发实例需改为实际路径。不能在运行中删除。它删除所有经历、知识、证据、索引、检查点、遗忘标记与用量；不删除原始会话、OM observations/reflections、人格或模型设置。重新启动更新后的实例时按当前结构重建。不承诺擦除文件系统快照、备份或原始会话中的正文。

## 四类知识与任务经历

| 类别 | 内容与边界 |
| --- | --- |
| 用户偏好 `preference` | 稳定开发／协作默认。区分用户明确表达与行为推断；单次任务例外不覆盖长期默认。不能从系统提示、仓库模板或工具输出推断个人偏好。 |
| 项目档案 `project` | 至多 320 字的项目身份：名称／别名、用途、可证实的用户参与和粗粒度技术栈。代码路径、文件名、API 与子系统实现属于项目知识，不进入档案；程序拒绝过长或带明显源码路径／TS 文件名的档案，模型还需判断语义分类。全局目录可发现，不等于全局常驻；不因为打开目录、查看代码或做一次审查就推断拥有／开发该项目。进展是历史已知状态，不是实时状态。 |
| 项目知识 `knowledge` | 已采纳决策、维护边界、可靠操作方式及难以重新发现的定位知识。不保留未经采纳的脑暴或常规状态日志。 |
| 经验教训 `lesson` | 适用场景 → 症状 → 已确认原因 → 有效修复 → 验证 → 限制。优先高收益、难发现的经验，不要求每次任务产出。 |
| 任务经历 `episodes` | 用户目标、关键尝试、结果、验证及不确定性。历史参考，不是默认指导。一个会话可以有多个任务，同一任务后续可更新同一经历。 |

知识有 `applicability`、来源性质、来源时间、更新时间、项目身份及 checkout 边界。没有模型自报的百分比可信度。结果为 success / partial / fail / uncertain；助手自称完成不能冒充工具验证。

## 来源与提取

实现：`sources.ts`、`learning.ts`、`hygiene.ts`。

- 从当前 leaf 沿 parent 链查找未处理后缀，遇持久化检查点停止；不使用跨分支 JSONL 文件偏移。
- 每个证据窗口先处理最早的新内容，通常不超过 24 个可见消息、16,000 UTF-8 字节、256 个 entry。过长文本有明确头尾摘录标记，剩余 entry 留待后续窗口，不假装全部检查过。
- 提供少量之前消息背景和最近最多三条当前分支已完成整合的经历。背景用于任务连续性，不是新的独立证据；只有本窗口带 ID 的直接来源能被引用。
- 收入用户消息、助手可见文字／必要的工具动作元数据、工具结果。命令只提供受限的 command，文件工具只提供 path，不复制 write/edit 正文或任意工具参数。
- 排除 thinking、隐藏 custom messages、OM 内部记录、branch summaries，以及 `memory_*`、`recall`、`session_*` 工具结果。用户 pastedText 附件按持久化元数据省略；图片只保留消息中的正常文字。引用／网页／工具结果内的指令不是用户偏好授权。
- 常见凭据形状命中时省略来源且拒绝其成为支持；输出经历／提议／知识再检查。不是通用脱敏或对所有个人信息的识别。
- 引用保存 session ID、session 文件、原始 entry ID、分支锚点、消息 digest、角色和时间。稳定 ID 基于完整来源位置，不按内容相似就合并独立证据。
- 提取允许 `episodes: []`；有效空结果也原子推进检查点。一次可返回最多 4 个任务，每个最多 6 个提议。经历可以有零提议。
- 任务 continuation 只能引用本次提供的同来源会话／项目／分支经历；累积来源有上限，不能无限扩大上下文。
- 引用未知／重复 ID、助手单独支持的知识、用工具输出证明个人偏好、单条用户证据冒充重复偏好等均由程序拒绝。行为推断至少需要两个不同用户消息 ID；语义稳定性仍由模型判断。

## 整合与更新

实现：`integration.ts`、`store.ts`。

经历和提议先与检查点同事务落盘，再独立整合；提取成功、整合中断可在重载后恢复，不重跑已完成提取。提议只保存受限证据摘录，不复制完整聊天或大段工具输出。

整合读取本任务、提议、同类相关既有知识。相关集合同时包括 FTS 命中和当前范围最近知识，减少新措辞找不到旧决策的问题。集合有预算；删减既有输入时明确报告省略，模型不能把未看到的知识当成不存在。

动作：

- `skip`：不产生知识，整合成功后立即删除临时提议；经历仍可作为历史参考。
- `add`：新增。完全一致且边界一致的知识自动合并支持，不靠重复增加可信度。
- `merge`：只补证据，不允许改写正文或适用条件。
- `revise`：用更新的直接证据精炼同一知识，不跨项目／checkout 扩张。
- `supersede`：更新的直接用户纠正或已验证实现替代旧指导；旧知识标记 superseded，不自动召回。
- `dispute`：保留双方、标记 disputed，检索显示未解决冲突。更新的明确证据可以 supersede 一个 disputed 目标并退役其相同边界内的冲突组，避免另一条旧冲突一直被召回。

目标必须来自本次提供的集合，类型、scope、项目身份与 checkout 边界一致。推断偏好不能替代用户明确要求。知识提交在短同步事务中重新验证 revision、任务／提议载荷；遗忘和删除优先于迟到结果。一个批次任一校验失败则全部回滚。

## 范围与检索

项目身份沿用可靠 Git common dir，否则真实 cwd；linked worktrees 共用项目身份。开发 Chat scratch 使用独立 `chat:<sessionId>`，不能继承外层开发仓库。

- 用户偏好和项目档案可全局发现；项目档案保留自己的 projectKey，不合并同名项目。
- 项目知识与经验默认 project 范围。工具验证的项目细节额外固定 `checkoutKey`，只在原 cwd 的后续会话自动使用，不能冒充 sibling worktree 的现状。
- 不记录未经证实的历史 branch／commit，也不把当前 checkout 信息倒推成历史验证。来源时间和适用条件不保证内容至今仍有效，修改代码前仍需读取现状。
- 不再有绕过筛选的常驻导航。全局项目档案不自动铺进每轮请求；当前项目身份沿用已有项目／cwd 上下文，不重复注入档案。明确偏好最多取 5 条、约 2800 字节作为候选，也必须通过适用性和增量价值筛选。旧的实现型项目档案不会自动重写或删除，但不参与自动召回。
- 自动检索按类别各取至多 5 条，最多 20 条；使用当前问题和少量前文检索，项目目录问题也可取项目档案。查询提示词表是双语检索提示，不是授权或硬任务分类。
- `relevance.ts` 用完整当前问题、最近两轮成功可见问答和本次实际请求中的少量可见上下文筛选 0–5 条。关键词／项目相似不足以录用，必须提供当前上下文尚缺的必要信息；语义改写重复也应拒绝。项目档案仅在用户询问对应项目或项目经历时适用。代码先排除当前有效可见问答中全文重复的内容，不拿已被压缩掉的整段历史做全文去重；模型判断语义重复仍需实际质量评估。
- 筛选总超时 60 秒（含模型准备、鉴权与完整输出，不仅是建立连接）；无候选不调用模型；失败不回退为原始 FTS 命中。同用户轮次、配置、范围、revision 复用结果，工具迭代不重复请求；复用时再次剔除已出现在当前可见上下文的全文重复。遗忘／切分支／任务取消使旧结果失效。
- 总注入限 6000 UTF-8 字节，只传精简引用：id、原文、适用条件，以及必要的来源 checkout／工具证据时间、推断或冲突提示；不发送 scopeKey/projectKey、存储创建／更新时间等数据库内部字段。
- 任务经历不冒充当前规则自动注入，可通过工具主动检索回查。所有注入与工具输出标为不可信历史数据，不改写系统提示，不写入 JSONL，不再被当成独立学习来源。

只读工具：

- `memory_projects`：分页发现项目档案，不代表授权读取项目细节。
- `memory_search`：按 `kind` 检索四类知识或 episodes。
- `memory_read`：读取完整知识／经历及分页证据引用。
- `memory_recall`：按 digest、session 和 ancestor 验证原始消息并分页读取。历史缺失／变化／截断明确报告；JSON、UTF-8、权限、IO 和树格式错误抛出，不能伪装成历史缺失。读取不修复、不迁移、不改写源文件。

后三个工具可带已知项目档案 `projectId` 定向读其他项目；仅在用户明确要求该项目时使用，工具说明约束授权，不能因列表出现就读取。main 只接受存在且有效的档案，按它记录的项目和来源 cwd 解析范围，不接受任意 scopeKey。子 Agent 不加载记忆。

## 调度、模型与用量

实现：`service.ts`、`extension.ts`、`worker.ts`。

- 开关默认关闭。与现有 OM namespace 的 longTerm 设置共用严格读写与配置队列；独立模型配置仍复用现有「长期记忆模型」。
- 未自选时继承 OM 模型与备用认证路径；自选模型不可用不静默回退。学习、整合、相关性各为独立无工具请求，不启动主 Agent 或递归 Agent。
- session_start / agent_settled / session_tree 后约 60 秒空闲才运行；同来源单飞，全局最多两个学习／整合任务。每轮做一次提取或一次整合，成功后让出事件循环继续积压。
- 用户开始任务、切分支、关闭／重载时取消。元数据追加不破坏仍在当前祖先链的来源，因此重命名不应丢掉结果或漏唤醒。
- 请求与鉴权准备总超时 60 秒；供应商忽略 AbortSignal 时，宿主仍及时结束等待并拒绝迟到写入。
- 作业按来源引用持久化，失败的作业保存指数退避（1 分钟至 30 分钟），重载不绕过。单任务输出问题不阻止其他就绪整合；共享配置／鉴权／限流／请求／存储故障暂停当前调度器。
- worker 的输入预算沿用现有保守 UTF-8 字节预算；先裁掉可选前文／相关知识，不悄悄将未读来源标为已读。截断输出、工具调用输出、非法 JSON 和结构校验失败不提交。
- 用量仅保存已完成模型响应的阶段级请求数、输入／输出 tokens 和 SDK 估算费用，无正文和凭据。无响应的取消／错误请求不计入这份聚合，因此不是完整供应商账单。用量写入失败固定告警，不阻止学习。
- 诊断只使用固定原因码，不记录原始异常／响应或正文。自动召回仍经既有 system-plugins:ui 提供最近轮次的实际注入诊断，不冒充模型思考。通知显示 `[stage/code]`，召回行显示错误码，展开可看阶段与可用的 HTTP 状态；失败缓存保留诊断并注明未重新筛选，取消不报失败。
- 请求错误细分为 `connection`（连接失败）、`connectionReset`（连接中断）、`dns`（域名解析）、`tls`（TLS／证书）、`providerTimeout`（供应商／传输超时，含 HTTP 408/504）、`httpClient`（其他 HTTP 4xx）、`httpServer`（其他 HTTP 5xx）；401/403 为 `authentication`，429 为 `rateLimit`。本地 60 秒截止为 `timeout`，与供应商超时分开。分类读取结构化 HTTP／网络码及有界 cause 链，并识别 SDK 字符串的已知前缀；不从响应正文任意猜测，证据不足保留 `request`，只回传固定码和数值 HTTP 状态，绝不回传原始错误字符串。

## 管理、删除与遗忘

设置 → 人格与记忆 → 长期记忆：五类分页查看，显示来源性质、适用条件、checkout、来源时间和状态。后台显示运行数、待处理数、最近成功、固定失败原因／重试时间及分阶段用量。自动流程不需要人工审核。

- 删除任务经历：删除其正文和未整合提议，保留处理记录；不会连带删除已经录用的知识，后者有独立的原始来源引用。
- 忘记正式知识：二次确认后删除目标及关联替代／冲突链、FTS、证据及派生经历／提议，保留无正文来源键。原始聊天不删除；其他知识的独立来源引用不受影响。
- 相同来源不能重放恢复；全新独立来源仍可能再次学到同一内容。永久主题排除规则尚未提供。
- SQLite secure_delete、FTS secure-delete、新目录 0700、数据库 0600；数据库坏 JSON／SQL／IO 失败不重置默认库。

## 验证与后续边界

自动测试不调用真实模型、不运行 E2E。覆盖原始消息投影、敏感内容和附件排除、窗口预算、首次基线／旧分支、事务检查点、任务续作、知识整合、checkout 隔离、冲突解决、遗忘与迟到结果、持久化退避、取消／快速续跑、只读源文件、UI-only IPC、分类界面、模型认证与相关性筛选。

模型是否正确理解稳定偏好、是否过度保存过程日志，需要真实模型质量评估；mock／结构测试不能证明这部分语义质量。使用 `tests/fixtures/memory-learning-cases.json` 的固定场景对提取和整合结果做人工／离线比较，不在正常测试里自动发请求。

尚未提供：全历史主动导入、显式“记住”快路、Agent 写入／遗忘工具、跨项目通用经验的自动升级、可靠历史 commit 共享、向量检索、自动经历过期淘汰和永久主题排除。
