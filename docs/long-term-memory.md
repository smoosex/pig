# 跨会话长期记忆

## 分层与入口

```text
原始会话 JSONL → observations → reflections → 待审候选 → 模型审核 → 正式知识库 → 范围内检索 → 模型相关性筛选
```

OM 负责当前会话压缩后继续任务；长期记忆负责后续会话找回偏好、项目决策和经验。Reflection 不自动成为事实，原始 reflection 仍以会话 JSONL 为权威来源。

入口：**设置 → 人格与记忆 → 长期记忆**。开关、模型和思考强度修改后自动保存并应用，无需点击保存。连续修改串行写入，旧回复不覆盖新选择；保存或应用失败会显示错误并重新读取持久化状态，写入失败恢复已保存值，应用失败不假装回滚已落盘的改动。

- 「自动筛选与召回」默认关闭；开启会额外调用模型。关闭不删除候选或正式记忆。
- 独立的模型与思考强度选择器；默认继承 OM 模型和鉴权备用模型。自选模型不可用直接报错，不静默改用会话模型。默认的继承模式沿用 OM 的思考设置；自选模型未选强度时为 off。
- 「查看长期记忆」分别展示待审候选和正式记忆，支持分页和刷新。候选只有「删除」，与审核 skip 共用删除逻辑；已入库候选保留为内部证据，不在候选列表展示。正式记忆提供来源引用和二次确认「忘记」，显示有效／已被更正／存在冲突。
- 配置仍在 `$PIG_DIR/plugins/observational-memory/settings.json` 的 `observational-memory.longTerm`；与其他 OM 设置共用严格读写及写入队列，不新增配置写入者。

## 候选和证据

代码在 `src/main/features/memory/long-term/`：

- `candidates.ts` 收集当前分支的 reflection 及完整来源位置：session ID、session 文件、cwd、reflection entry ID/记录序号/ID、observation entry ID/记录序号、原始 source entry IDs。
- `service.ts` 在 reflection 落盘后增量登记候选；启动、重载与切分支时从当前 leaf 沿 parent 链补漏，遇到持久化的已处理 entry 即停止。候选与来源 entry 检查点同事务提交；检查点独立于候选正文，删除候选不会导致同来源重新收集。只处理已存在的磁盘会话，不扫描所有历史会话或废弃分支。
- 无新增 reflection 时不调用 `getBranch()`；存在新增 reflection 时展开一次当前分支验证祖先证据，只构造未处理 entry 中的候选。首次同步需扫描当前分支一次；之后切到未处理过的分支仅收集新增祖先路径。检查点依赖 SDK entry 不可变及 parent 链稳定，不使用跨分支的 JSONL 文件偏移。
- 来源缺失、前向、歧义或空支持关系拒绝收集。custom messages、branch summaries、`memory_*`、OM `recall` 和 `session_read` 工具输出不能成为独立新证据。
- 不复制原始消息正文到数据库。常见凭据形状初筛会排除候选／来源／输出事实，但不承诺通用脱敏。
- 收集失败只警告，不回滚 reflection，也不阻止 OM Dropper。再次打开来源会话会补漏。

## 空闲审核

`extension.ts` 在 session_start、agent_settled 和切分支后安排后台审核；先等本会话正在进行的 OM 整理完成。按 sessionManager 与 leaf 缓存分支快照，从数据库待审队列按 reflection entry 的分支归属筛选，不重新派生所有历史候选。每次最多一条候选，同会话单飞，仅审核当前来源会话和当前分支。成功（包括 skip）后让出事件循环，再继续下一条，直到积压处理完或不再空闲；不启动递归 Agent、工具循环或额外主 Agent 轮次。

单条超时、输出／证据校验失败、入库 revision 冲突会将该候选退避，让其他候选继续；配置、鉴权、限流、供应商请求或存储故障暂停整队，避免逐条重复请求。空闲期间定时重试，退避从 1 分钟开始指数增加，最高 30 分钟，成功后清除；额外空闲事件不绕过退避。退避仅保存在当前扩展实例内，任务／分支切换不会重置，关闭／重载后不保留。修改设置触发资源重载后重新尝试，不永久标记候选失败。

`reviewer.ts` 发出一次无工具请求，复用 OM 的模型认证、供应商组合流和会话头。明确给出 reflection、最小直接消息摘录及相关既有记忆。来源不含 thinking／附件／工具参数；长文摘录有明确省略标记。总输入按 UTF-8 字节保守预算，必要时明确标记头尾摘录并保留来源地址与角色；既有事实不截断，超出其预算时明确告知省略。保留的直接来源不能证明结论时应跳过，最小请求仍超预算则报错。输出预算受模型窗口限制。JSON、字段、候选覆盖、目标范围、直接来源角色全部严格检查，截断、异常和工具调用输出不入库。

只允许用户陈述和工具验证两种来源类型；助手单独宣称完成不能晋升。动作：

- `skip`：在审核提交的同一事务内立即删除候选正文，不生成事实，也不保存 `skipped` 审核记录；只保留不含正文的来源 entry 检查点，防止重放重新导入。无需定时清理或人工确认，其他待审和已录用候选不受影响。
- `add`：新增；同范围、同规范正文的活跃事实合并来源。
- `merge`：同一核心事实仅补证据，不改正文，不提高可信度。
- `supersede`：只接受时间更新的直接用户纠正，旧事实保留为 superseded，不再自动召回。
- `dispute`：保留双方并都标为 disputed，检索明确展示冲突。

用户开始任务、切分支或关闭／重载立即取消审核及待执行的唤醒定时器；切分支后只按新分支重新调度。模型解析／鉴权与请求的超时为 60 秒，等待 OM 整理不占此预算。模型迟到不能提交；提交前重新核对配置、来源分支的 manager/leaf 身份、空闲状态和知识库 revision；来源 leaf 改变即放弃本次结果，不重扫历史。失败保留 pending 候选，不改已有事实。

警告携带固定的原因和错误码，区分配置／模型不可用、鉴权、限流、请求、超时、输出截断、JSON、字段／证据校验、上下文预算、入库冲突和存储错误。main 的 `[long-term-memory] review failed` 日志仅含固定错误码／阶段、耗时、候选 ID、已解析模型（解析前为指定模型或 inherited）及重试策略；不输出原始异常、供应商响应、凭据或对话正文。

## 当前范围策略

- **global**：仅明确的长期用户偏好。
- **project**：明确采纳的项目决策或可复用经验。通过只读文件系统识别 Git common dir，可靠识别的 linked worktrees 共用项目身份；其他目录按真实 cwd 隔离。
- **session**：成果、工具验证结论暂时只限来源会话。

当前 checkout 不能证明历史消息的分支或 commit，因此首版宁可缩小成果范围，不自动扩散到项目，更不冒充主分支已有。开发实例的 Chat scratch 即使位于 Pig 仓库内，也使用独立 `chat:<sessionId>` 身份，不能继承外层仓库记忆。

## 存储与并发

`store.ts` 使用 Node 内置 SQLite，文件 `$PIG_DIR/memory/long-term.sqlite`，新目录 0700、文件 0600，无新增原生依赖。

仅维护当前表结构，不设数据库版本号，不提供旧库兼容或迁移。包含：候选、审核状态、正式事实、证据关系、FTS5 索引、知识库 revision、防重导 tombstones 和 `(session_id, entry_id)` 来源处理检查点（不存正文）。完整来源位置 SHA-256 作为候选幂等键；相同来源键不同载荷报错。数据库损坏或 SQL 执行失败直接抛出，不重置为空库。

模型请求不持有数据库事务。最终一批审核在短同步事务里校验 revision 和候选载荷；其他会话的纠错或用户忘记优先，旧结果整批拒绝。重复转述和相同 reflection hash 不增加独立确认次数。

## 读取

- `search.ts` 使用 CJK 单字／双字词项和 FTS5；中文检索不依赖空格。无需 embedding 或向量数据库。
- 自动召回先用当前用户文本（检索查询限前 2000 字符）做范围内 FTS 检索，最多取 20 条，再由 `relevance.ts` 用完整当前问题＋最近两轮成功的用户/最终回复筛选 0–5 条；前文每条最多约 1000 字符，排除思考、工具结果、中间工具调用、隐藏注入及失败/中止回复。只同项目或关键词相似不算相关，默认宁缺毋滥。模型只返回本批唯一 ID，严格拒绝未知 ID、重复、额外字段及截断输出，注入数据库原文，不允许重写或编造。只取模型筛选后且满足 6000 UTF-8 字节预算的事实；范围仍仅全局＋当前项目＋来源会话，排除 superseded，disputed 保留冲突标记。
- 相关性筛选与入库审核共用「长期记忆模型」配置、认证和组合流（`worker.ts`）；未自选时继承 OM 模型及备用模型，自选模型不静默回退，沿用该配置的思考强度。不调用工具；无候选不发请求。有候选时会增加一次前台模型请求及等待，解析/鉴权/请求总超时 10 秒；输入超预算先删除旧前文，再移除低排名候选，问题和单条记忆不截断。空选择不注入；错误/超时同样不注入，不回退为原始 FTS 命中。
- 同一用户轮次、模型配置、访问范围与知识库 revision 不变时复用筛选结果（包括空/失败结果），不在每次工具迭代中重复请求。任务信号中止、开始/结束、切分支、关闭或新检索替代旧检索时取消等待并拒绝迟到结果；完成前复核来源 manager/leaf、配置、范围和数据库 revision，筛选期间遗忘或变更的记忆不能继续注入。
- `context` hook 把带有程序来源说明的**不可信历史数据**临时追加到请求末尾，不改系统提示词，也不写入 JSONL，因此不会被 OM 当作新消息再次观察。记忆不能覆盖当前请求或项目规则。
- 自动召回通过已有 `system-plugins:ui` 通道发送独立状态，推理区展示检索中、命中条数、未命中、失败和取消；展开显示实际预算内的正文、范围和冲突标记及耗时，不冒充模型思考或核实结果。事件不传查询原文或文件系统 scope key，不写 JSONL。每个标签最多保留最近 32 轮的诊断，重载应用不恢复；会话关闭或资源重载清理，迟到结果不能覆盖新请求或复活已关闭会话。
- `memory_search` 按范围搜索正式记忆；`memory_read` 读取事实与证据指针；`memory_recall` 从记录的会话文件和 branch 精确读取来源，校验原始 reflection／observation 地址，分页并标明缺失、变化和截断。来源文件严格只读加载，旧版本仅在内存迁移，不补换行、不初始化或重写文件；缺失路径（ENOENT／ENOTDIR）及空文件返回不可用，权限、IO、UTF-8 解码、JSON 和会话树格式错误直接抛出，不能伪装成历史缺失。必须跟随分页才能声称完整覆盖。
- 原有 OM `recall(id)` 仍只回溯当前分支，不改语义。上述三个只读工具仅在人类会话加载；子 Agent 不加载人格或记忆功能。

## 忘记与边界

候选的手动删除与自动跳过共用同一 pending-only 操作：删除正文、保留来源处理检查点，不写入用户主动忘记的 tombstones。候选已经入库时拒绝删除，不能借候选入口连带删除正式记忆。只有正式记忆提供「忘记」：删除正式事实、全文索引和关联候选／证据，保留不含正文的来源键，防止同一来源重放复活。SQLite secure_delete 与 FTS5 secure-delete 启用；不宣称擦除原始会话、外部备份或文件系统快照。独立的新来源不是同一个防重导键。

尚未实现：直接「记住这件事」快路、Agent 写入／忘记工具、可靠的历史 branch/commit 成果共享、语义向量召回、有效期淘汰、全历史后台扫描及审核用量面板。候选仍需经过现有 Reflector 阈值；设置页来源引用不是原始对话展示。
